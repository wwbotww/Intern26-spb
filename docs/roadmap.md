**不是正在执行的开发计划**；不完整物流接口保持遗留。已交付能力见[当前状态](current-status.md)。

## 1. 体验与数据治理

- 正式 API/Web 已完成限定发布，不再保留旧 `a2fb398` 首页发布任务；目标页面的人工点击/刷新验收仍待补。
- 建立经审核的政策正负例：投诉渠道、申诉前置条件、理赔材料证据不足；
  分别核对路由、检索、证据充分性和页面呈现。
- 核对 RAG 文档有效期、草案/正式、地区和来源优先级。缺企业办理指南时继续有依据拒答。
- 设备/生鲜记录来源覆盖、新鲜度及维护人；缺型号/地区不放松硬约束，不把旧观察当实时价。

如启动，退出条件：目标页面交互有记录；正例成功、负例正确拒答；数据不足与依赖故障可区分。

## 2. 全品类价格：限定发布后的剩余范围

A～D 已交付，E 的有限真实联调、CI、备份恢复及 API/Web 协调发布已完成。
保留[原实施计划](product-price-implementation-plan.md)作为设计与门禁依据，具体缺口只维护于其 PRICE-G 表。

| 剩余任务 | 依赖与验收 |
| --- | --- |
| 五品牌完整设备语义、无金额状态推进、更广市场/规格 | 生产者的独立样例、身份/match/规格/状态证据；不以行数或单品牌成功代替完整能力矩阵 |
| 公司库 V2 SELECT-only 账号 | 环境方核对实际权限；本地两版隔离 MySQL 已通过，不擅自改生产授权 |
| 来源 freshness 与覆盖维护 | 数据维护人确认更新周期/阈值；未知、超期、当天无价分别呈现 |
| 可选最近有价历史 | 证明同 revision 和 correction 终点后实现有界查询；当前 SQL 保守不返回，不用历史填现价 |
| 旧 SQL / 默认 device_v1 清理 | 先核对消费者、目标覆盖及回退方案；catalog 当前无自动 fallback，不等于旧代码已物理移除 |
| 正式页面与回滚补验 | 人工验证目标浏览器；正式回滚另确认窗口和会话影响，不能让旧镜像打开 State 4 |

“全品类模型已接入”与“五品牌旧能力全替换”分开。扩大范围不隐含采集、修复业务行、删除旧表或发布授权。
架构取舍见 [ADR-0020](adr/0020-unified-product-price-query.md)。

## 3. 独立 Understanding 质量验收

- 收集未见、按语义 group 隔离的候选与困难负例，覆盖多意图、否定、纠错、地区和商品歧义。
- 实际审核者完成 `understanding-review` / `understanding-freeze`，不自动代签。
- 冻结代码、规则、Prompt、字典、Gold 与配置，另获预算后做 Rules/Hybrid 同样本对照。
- 联合 V2 多轮回归验证补槽、冲突确认、恢复、错误 Tool 和任务完成，不只看组件 F1。
- 资费“不需要保价”等保守规则误拒须有专项评测后再调整，不为未接通接口提前放宽范围。

如启动，退出条件：独立数据与审核证据、失败/未知用量保留、指标分母明确、回归可解释。
现有 48 条 development 和历史模型授权不能复用为新的 holdout/调用许可；
操作与指标定义见 [Eval 指南](../eval/README.md)。

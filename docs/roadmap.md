# 后续路线图

范围依据：[当前状态](current-status.md)。前一轮单实例内网交付已经收口；本文只保留未完成工作。
原 Phase 编号仅作为代码/测试的历史检索标识，不要求继续按编号串行开发。

## 1. 当前体验与数据覆盖：优先，不等物流接口

- 核对首页修正 `a2fb398` 的远程 CI、实际 Web 发布版本和目标页面人工验收。
  只更新预期组件，保留当前 Web 和回退点，不因 UI 更新改 API、签名或状态库。
- 建立经审核的正例和负例：投诉渠道、申诉前置条件、当前有价型号、缺失历史型号、
  理赔材料证据不足。分开记录路由、检索、证据充分性、结果状态和页面呈现。
- 核对 RAG 文档有效期、草案/正式、地区和来源优先级。没有获准的企业办理指南时继续拒答。
- 设备价格增加数据覆盖/新鲜度检查；是否补历史型号由业务范围决定，不放松型号硬约束。

退出条件：目标页面交互验收有记录；正例成功、负例正确拒答；数据不足与依赖故障可区分。

## 2. 价格数据 V2 适配：中到大型独立扩展

前置：[数据源边界](data-sources.md)中的生产者/消费者契约与最小类目范围确认。

1. 冻结 V1 兼容行为，确定全品类查询所需类目、品名、地区/市场、时间、单位和价格口径。
2. 明确消费 listing/observation 还是规范商品层；不能假定后者已填充。
3. 在 Repository/Tool/DTO 边界新增适配，不把生鲜批发价塞入设备 SKU 匹配器。
4. 同步 API、生成 TS、运行时校验、Renderer 和 Eval；先少量类目，再扩大覆盖。

退出条件：保留 V1 回归；不同单位、批发/零售、日期和来源不混价；缺失字段不伪造；
当前与历史观察有可审查的查询示例。任务尚未完成，不隐含数据采集/导入授权。

## 3. 独立 Understanding 质量验收：可并行准备

- 收集未见、按语义 group 隔离的候选与困难负例，覆盖多意图、否定、纠错和地区歧义。
- 实际审核者完成 `understanding-review` / `understanding-freeze`，不自动代签。
- 冻结代码、规则、Prompt、字典、Gold 与配置，另获预算后做 Rules/Hybrid 同样本对照。
- 对应 V2 多轮回归验证补槽、冲突确认、恢复、错误 Tool 和任务完成，不只看组件 F1。
- 特别处理资费“不需要保价”等保守规则误拒；有专项评测后再调整范围理解。

退出条件：独立数据与审核证据、失败/未知用量保留、指标分母明确、回归可解释。
现有 48 条 development 和历史模型授权不能复用为新的 holdout/调用许可。
操作与指标定义统一见 [Eval 指南](../eval/README.md)。

## 4. 物流真实接口：按资料到达推进

| 工作 | 前置 | 退出条件 |
| --- | --- | --- |
| 轨迹 T4 | [轨迹确认清单](../apps/assistant-api/docs/integrations/tracking.md)及授权访问条件 | 独立签名向量、真实成功/空结果/失败样例、脱敏联调记录、JSON/SSE 回归 |
| 资费 P4 | [P-G01～P-G12](../apps/assistant-api/docs/integrations/postage.md)中基础询价所需合同 | 产品/地区/两层签名/金额确认；受控真实 transport、计价身份及恢复兼容回归 |
| 时限接入 | 接口文档、单位、计算基础、业务日/自然日与时区 | Adapter + Mock 故障集 → 授权真实互通 → 公开结果验收 |
| 正式地域目录 | 获准来源、供应商编码/粒度、版本与更新机制 | 替换 8 条 Demo 目录，直辖市/歧义/未覆盖地区测试通过 |

资料不足时保持 unavailable；前端使用正常业务提示，不解释项目开发进度。
签名、响应、单位、权限问题不能仅靠网络可达而关闭；缺口关闭须记录证据版本和影响范围。

## 5. 运维与扩容：按实际要求硬化

这些不是已完成内网交付的追溯性阻塞项，也不意味着目前已经具备。

| 范围 | 待做工作 | 验收要求 |
| --- | --- | --- |
| 可观测性 | 实际监控接入、告警与保留策略 | 故障可定位，遥测失效不影响业务，记录真实而非合成 SLO |
| 安全与依赖 | 受支持 OS/Docker、TLS、Python/OS 扫描、密钥托管 | 维护人和更新/回退流程明确；不擅自升级共享主机 |
| 存储 | 跨版本迁移、加密异地/保留、备份外删除记录、未完成 claim 恢复策略 | 不覆盖旧库；owner/TTL/幂等有效；恢复目标可测 |
| 身份 | 登录/RBAC、个体撤销、业务授权与计价资格 | 代理 Key / 匿名 Cookie 不代替租户或客户资格 |
| 多副本 | 共享 checkpointer、协调/幂等/配额/熔断 | 跨实例冲突、故障转移和重放测试；不能直接增大 workers |
| CI/CD | 分支保护、报告长期留存、镜像发布策略 | 提交、镜像、部署可追溯；当前 CI 不自动发布 |

## 维护约定

- 任务写清范围、依赖、验收条件；完成后更新当前状态，从路线图移除或简记关闭。
- 小修复放提交说明和测试，不再新建 Phase 文档；新架构决策才新增 ADR。
- 接口缺口在 integration 文档维护，此处不复制全部协议细节。
- 发布只追加压缩证据；复盘只保留能讲清楚的设计故事。

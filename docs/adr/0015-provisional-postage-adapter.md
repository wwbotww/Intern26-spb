# ADR-0015：用具名临时合同打通资费离线适配，不推定真实互通

- 日期：2026-09-09
- 状态：Accepted / P2 offline verified
- 补充：[0014 定价上下文](0014-explicit-postage-pricing-context.md)、[0013 语义熔断与受控装配](0013-controlled-tracking-composition.md)

## 背景

资费文档缺少可用业务报文样例、产品字典及完整金额语义，真实服务不可访问。用户要求
记录缺口并先完成已有条件下的通路。仅返回领域 Fake 数据无法验证签名 / 编码 /
协议映射；自动猜测多个合同又会使失败不可解释，甚至展示错误金额。

## 决策

1. 新增独立 PostalPostageGateway，固定一个 synthetic provisional profile，借助
   MockTransport 完成字节传输到 Graph / SQLite / 收据路径；生产入口不装配此适配器。
   不提供真实地址或自动网络模式，fixture 只在测试 harness 中注入。
2. 业务 / CSB signer 独立，序列化一次、先签原文再 form 编码；不得复用轨迹签名、
   探测算法变体或用 MD5 兼容名义关闭 TLS / 平台安全限制。
3. profile 的非敏感语义指纹与目录共同进入执行条件，跨重启变更必须新查询；密钥
   不进入状态。真实身份 / 客户计价绑定仍是显式缺口，不以 hash 代替业务授权。
4. 四层成功门禁后再产生报价；明确金额字段与单位，不取缺省金额，不累加未知包含
   关系费用，不把输入重量当计费重量。未知响应字段和原始错误消息不进入收据。
5. Gateway 统一拥有语义熔断；技术 / 契约失败计一次，已识别计费拒绝不重试且证明
   协议路径健康，取消释放半开探测。Graph 仍是唯一重试预算所有者。
6. 开发缺口按外部合同与内部交付分开，P3 公开装配 / Web / Eval 不必等 P4 网络恢复，
   但真实 transport 与最终价格解释必须等独立合同确认及调用授权。

## 结果与代价

新增 160 项离线测试，全量 887 项通过；可复跑烟测验证补产品、SQLite 重启、报价、
重放零请求和新查询刷新。外部合同未确认、公开资费 UI 未完成，不能宣称真实接口接入。
严格单 profile 会拒绝可能合法但尚未确认的结构和单位；后续以独立证据更新明确版本，
而不是增加“解析到成功为止”的兼容分支。详见 [P2](../agent-kernel-phase3b-postage-p2.md)
和[缺口台账](../agent-kernel-phase3b-postage-gaps.md)。

# ADR-0012：执行幂等不等于结果缓存

> 决策记录：下文验收范围保留为记录当时的事实；现状见[当前状态](../current-status.md)。


- 状态：Accepted / Phase 3B-T T2 local verified
- 日期：2026-09-09
- 关系：补充 ADR-0004 的存储边界与 ADR-0005 的重放策略，不替代其分层 / Failure 决策。

## 背景

阶段 1 的 Tool 收据主键 `(conversation_id, argument_fingerprint)` 能处理节点重放，
但同一会话中用户再次查同一个邮件号时，也会得到旧状态或旧 no_match。旧测试甚至把
这种行为当成正确的“避免重复调用”。上游轨迹会变化，执行去重与业务缓存必须分离。

## 决策

1. 引入跨补槽 / retry 稳定的 query_id；新查询生成新身份，不直接使用不断变化的消息 turn_id。
2. 在查询命名空间内生成 tool_call_id；Repository 按会话和调用 ID 查找。
   Command SHA-256 仅用于参数一致性，调用预算和 reused 信号也按执行身份判断。
3. API 幂等继续由消息收据负责。已完成响应和同一执行的历史重放返回原观察值，不刷新时间；
   用户新键、新查询重新取数。
4. 旧收据事务复制到新索引，保留原行；仅从可校验的旧 pending action 恢复旧执行身份。
   不以会话 / 参数匹配作为兼容回退；删除 / TTL 同时清理两表。
5. State v3 的迁移增量随实际 Node update 持久化，保持 interrupt 和 sync/async 调度形态。
   无法证明身份时失败关闭，不猜测或伪造迁移事实。
6. 结果进入收据和公开回复前校验；轨迹 Port 返回含来源、profile、观察时间和完整性声明的
   类型化封装，空结果也可追溯。公开来源 UI 留给 T3 的契约演进。

## 未选择的方案

- 关闭收据：会破坏已完成 Tool 的 checkpoint 重放保护。
- 给旧缓存加一个 TTL：可以减少过期时间，却仍混淆主动刷新和执行幂等，且没有供应方缓存口径。
- 直接以最新 turn_id 作主键：补槽 / 恢复会改变消息身份，不能稳定识别同一业务查询。
- 用一份新 Graph State 覆盖所有旧 checkpoint：可能丢失 interrupt、历史和恢复点。
- 把 MD5 签名或 provenance 标签视为真实性证明：本次只实现受控协议与配置声明，未做供应商互通。

## 结果与限制

58 个新增离线用例和全量 `585 passed` 证明本地双后端查询刷新、重放、迁移、清理和来源
语义。接口调用仍为 Mock，公开 V2 schema 不变，默认生产装配关闭。

上游执行与本地收据写入没有共享事务；硬崩溃、跨进程协调和计费 exactly-once 不在已验证
范围。旧表保留不代表可随意回滚旧二进制，升级 / 回退需要单实例停机与一致数据库快照。

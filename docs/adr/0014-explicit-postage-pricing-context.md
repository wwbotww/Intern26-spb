# ADR-0014：资费操作绑定显式定价上下文

> 决策记录：下文验收范围保留为记录当时的事实；现状见[当前状态](../current-status.md)。


- 日期：2026-09-09
- 状态：Accepted / P1 local verified
- 补充：[ADR-0012 查询作用域收据](0012-query-scoped-tool-receipts.md)

## 背景

已有资费槽位要求两地与重量，而文档要求产品且存在多种计费口径。地名被解析、模型
输出产品码、HTTP 返回成功，都不能单独证明可以执行或已经得到有效报价。恢复期间
配置变化也可能令相同用户输入对应另一种价。

## 决策

1. 将产品 / 地区目录和范围校验放入可注入的纯服务；模型不能选择未在输入与目录中
   落实的产品。LangGraph 只编排补槽、冲突确认、有限重试与恢复。
2. 在生成参数指纹前固定产品、计费地区、整数克、币种 / 金额口径和目录内容指纹；
   补槽恢复时检测配置漂移，不悄悄重建旧查询的默认条件。
3. 严格路径要求类型化报价观察与来源；未知金额不补零、不从多金额字段中自动挑一个，
   不用本地加和或模型替上游算价。非法事实不落收据。
4. 旧完成结果保留未知依据，旧命令 null 新字段不改变原参数指纹；旧未完成查询未经
   范围检查则要求重启，不凭空补充证明。State v3 保持增量兼容。
5. 只将内部契约用于 P1；公开报价依据另在 P3 按 API / Web / Eval 一起演进，避免新增
   Domain 字段自动泄露计费绑定。真实资费仍默认未装配。

## 代价与限制

- 新严格路径需要同时注入前置策略和 Gateway；历史 Fake 兼容路径不适用于生产接入。
- 保守范围规则可能误拦截否定表达，也不能覆盖全部隐含条件，需要后续结构化确认与评测。
- 配置变更会终止尚未完成的询价，需要用户重新发起；这是防错价的明确取舍。
- 86 项新增测试、完整 `727 passed` 只证明合成领域与工作流行为；协议兼容、计费口径和
  真实互通尚未确认。详见 [P1 实现说明](../../apps/assistant-api/docs/integrations/postage.md)。

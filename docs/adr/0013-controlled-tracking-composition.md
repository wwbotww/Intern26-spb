# ADR-0013：受控物流装配与一次尝试的语义成功边界

- 状态：Accepted / Phase 3B-T T3 local verified
- 日期：2026-09-09
- 关系：补充 ADR-0005 / 0007 / 0012，不替代其 Failure、V1/V2 并行与查询作用域决策。

## 背景

将 Fake 换成 Postal Adapter 还不足以开放服务：无鉴权 Demo 不适合业务事实，生命周期
需要统一归属，领域来源未公开，HTTP 200 也可能包含跨单号或非法业务字段。新增公开字段
还会影响严格的 Eval 镜像和浏览器恢复，不能只更新一个前端类型声明。

## 决策

1. 组合根默认关闭，启用 V2 须有鉴权和显式 SQLite 路径；轨迹有独立开关和显式 profile。
   缺少合同不注册能力，不以 Fake 补位；可用性判断先于补槽。
2. 生命周期由组合根拥有；新资源用 AsyncExitStack 逆序关闭，V1 Tool 只借用，不重复
   初始化或关闭。默认 V1 行为和生产 Compose 不随本地验收自动改变。
3. Postal Gateway 统一管理一次尝试的熔断记账，HTTP 在该路径只做单次传输与错误翻译。
   HTTP / JSON / wire / 领域投影全部通过才计成功；不重复计算失败，不把局部配置故障、
   取消或熔断拒绝视作一次上游失败。重试仍由 LangGraph 独占。
4. readiness 读取本地状态，不通过实际邮件查询探测服务，避免成本、隐私和压力副作用。
5. 公开来源采用单独白名单 DTO，不直接序列化整个 SourceReference；同步 JSON/SSE、
   OpenAPI、生成类型、前端运行时验证及独立 Eval 镜像。旧字段缺失保留未知，不伪造当前来源。

## 未采用

- 直接开放 Demo：默认无鉴权且有合成数据，不是受控业务组合根。
- HTTP 与业务两层分别熔断：同一请求可能重复记账，HTTP 200 提前恢复健康也会掩盖业务错误。
- 把所有上游异常设为 retryable：未知业务码和错误文本不能提供重试依据。
- readiness 发一次真实邮件请求：会增加费用 / 查询权限依赖，也不适合每次健康检查执行。
- 领域对象直接透传前端：未来扩展 private record / URL 字段时可能意外泄露。

## 结果与限制

本地验证 56 项新增 Python、12 项新增 Web 用例和浏览器流程；没有真实物流请求。
尚无供应商确认、生产 SLA 或跨系统 exactly-once 证明。共享代理 Key 的 owner 不是完整
访客身份系统；公开发布前需 T4 合同 / 授权与 6A 身份、持久化、备份、CI 和回退验收。
